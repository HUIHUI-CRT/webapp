## 0. 先建立整体印象（30 秒）

```
浏览器
  │  ① HTTP 请求（页面 / 接口）      ② WebSocket 帧（聊天、画布）
  ▼                                     ▼
Uvicorn（ASGI 服务器，监听 0.0.0.0:8000）
  ▼
IdentityMiddleware  backend/app/auth.py  ← 没登记昵称：页面跳登记页 / 接口 401 / WS 拒绝
  ▼
FastAPI 应用  backend/app/main.py
  ├── /api/login /api/logout /api/session → backend/app/main.py
  ├── /api/posts*              → backend/app/routers/blog.py    → SQLite
  ├── /api/files* /api/upload  → backend/app/routers/files.py   → SQLite + uploads/
  ├── /api/tasks* /api/polls*  → backend/app/routers/workspace.py → SQLite
  │   /api/activity /api/stats /api/search
  ├── /api/health /api/rooms   → backend/app/main.py
  ├── /ws                      → backend/app/routers/ws.py      → 内存房间（services/hub.py）
  └── 其余所有路径             → frontend/ 下的静态文件
```

四个关键事实：

1. **只有一个进程、一个端口。** HTTP 接口、WebSocket、前端页面全在 `8000` 上，不需要额外开端口或防火墙规则。
2. **身份门禁在最外层。** 任何请求（含 WebSocket 握手）都要先过 `IdentityMiddleware`，没登记昵称就拿不到数据。
3. **前端没有构建步骤。** `frontend/` 里的 HTML/CSS/JS 原样被服务，改完刷新浏览器即可生效。
4. **C++ 扩展是可选的。** 没编译时自动走纯 Python 实现，接口行为完全一致。

### 2.2 请求进入后先过身份门禁、再匹配路由

中间件是「包在路由外面」的一层，所以它比任何路由都先执行：

```
请求进入
  │
  ├── AuthMiddleware            backend/app/main.py:84 → backend/app/auth.py
  │     ├─ 公开路径（/api/health、/login.html、/css/* …）→ 放行
  │     ├─ 会话 Cookie 验签通过                          → 放行
  │     └─ 否则：页面 302 → /login.html?next=…
  │              接口 401 JSON
  │              WebSocket 握手直接关闭
  ▼
  ├── CORSMiddleware            backend/app/main.py:89
  ▼
  └── 路由匹配（顺序如下）
```

```
① /openapi.json /docs /redoc        ← FastAPI 自带
② app.include_router(blog.router)    backend/app/main.py:99   → /api/posts*
③ app.include_router(files.router)   backend/app/main.py:100  → /api/files* /api/upload /api/download/*
④ app.include_router(ws.router)      backend/app/main.py:101  → /ws
⑤ @app.get("/api/health") 等          backend/app/main.py:168-198
⑥ @app.get("/") 重定向到首页          backend/app/main.py:204
⑦ app.mount("/", StaticFiles(...))   backend/app/main.py:216  ← 必须最后
```

两个顺序约定：

1. **身份门禁在最外层**。`add_middleware` 是「后添加的包在外层」，所以先加 Identity、后加 CORS，
   最终 CORS 在最外面——预检请求（OPTIONS）由 CORS 直接应答，不会卡在身份检查上。
2. **静态挂载在最后**。`StaticFiles` 挂在 `"/"` 上会兜住**所有**未被前面命中的路径。
   如果把它写在 ②之前，`GET /api/posts` 会被当成「找 `frontend/api/posts` 这个文件」
   而返回 404 —— 这正是计划书风险表里「静态文件路由冲突」那一条。

### 2.3 一次 `POST /api/posts` 的完整旅程

以「博客页点发布」为例，逐层对应到代码：

| 步骤 | 发生了什么 | 位置 |
|---|---|---|
| 1 | 用户提交表单，JS 组装 JSON | `frontend/js/blog.js`（表单 submit 处理） |
| 2 | `fetch('/api/posts', {method:'POST', headers:{'Content-Type':'application/json'}, body})` | `frontend/js/common.js:31` 的 `api.post` |
| 3 | Uvicorn 收到请求，交给 ASGI 应用 | `backend/app/main.py`（`app`） |
| 4 | CORSMiddleware 处理跨域头 | `backend/app/main.py`（`add_middleware`） |
| 5 | 按 2.2 的顺序匹配到 `POST /api/posts` | `backend/app/main.py:84` → `blog.py:84` |
| 6 | Pydantic 用 `PostCreate` 校验请求体；标题为空直接 422 | `backend/app/schemas.py` |
| 7 | 依赖注入创建 SQLite 连接 | `backend/app/db.py:78` |
| 8 | 执行 INSERT，回读完整记录（拿数据库生成的 `created_at`） | `backend/app/routers/blog.py:84-108` |
| 9 | 按 `response_model=Post` 序列化成 JSON，状态码 201 | `backend/app/main.py:84` 的 `status_code=201` |
| 10 | 请求结束：依赖收尾自动 commit + close | `backend/app/db.py`（`get_conn`） |
| 11 | 前端拿到新文章 ID，刷新列表并打开详情 | `frontend/js/blog.js` |

### 2.4 一次 `POST /api/upload` 的完整旅程（multipart）

这是全项目最复杂的一个 HTTP 接口，因为它要处理二进制流。

| 步骤 | 发生了什么 | 位置 |
|---|---|---|
| 1 | 页面把文件塞进 `FormData`，用 XHR 发送（为了拿到上传进度） | `frontend/js/common.js:31` 的 `api.upload` |
| 2 | 请求头是 `Content-Type: multipart/form-data; boundary=...`，字段名 `file` | `frontend/js/files.js` |
| 3 | FastAPI 用 `python-multipart` 解析分段，`File(...)` 参数变成 `UploadFile` | `backend/app/routers/files.py:81` |
| 4 | 清洗原始文件名（去掉目录成分与危险字符） | `backend/app/routers/files.py:45`（`sanitize_name`） |
| 5 | 生成 UUID 作为磁盘名，确定落盘路径 | `backend/app/routers/files.py:81` 附近 |
| 6 | **1 MiB 一块**地读请求体并写盘，同时累计大小做上限检查（超限 413 并删除半成品） | `backend/app/routers/files.py:81` 的 `while True` 循环 |
| 7 | 计算 SHA-256：装了 C++ 扩展走 C++，否则走 `hashlib` | `backend/app/ext/__init__.py:70` / `backend/app/ext/fallback.py:18` |
| 8 | 若库里已有相同哈希 → 删掉本次副本，返回已有记录（**秒传**，`duplicate: true`） | `backend/app/routers/files.py:81` 的秒传分支 |
| 9 | 否则 INSERT 元数据（存储名、原始名、大小、哈希）并回读 | `backend/app/db.py:18` 的 `files` 表 |
| 10 | 返回 `{ok, file:{..., download_url}, duplicate, engine}`，状态码 200 | `backend/app/schemas.py` 的 `UploadResult` |

内存要点：第 6 步决定了**上传 1 GB 文件时进程内存占用依然是常数级**，
这是计划书稳定性验收里「上传大文件时内存占用稳定」的实现方式。

### 2.5 一次 `GET /api/download/{filename}` 的完整旅程

| 步骤 | 发生了什么 | 位置 |
|---|---|---|
| 1 | 页面上的下载链接直接指向 `download_url`（浏览器原生下载，不走 fetch） | `frontend/js/files.js` |
| 2 | 路径参数 `filename` 是**存储名**（UUID），不是原始名 | `backend/app/routers/files.py:160` |
| 3 | 第一道关卡：必须能在 `files` 表里查到该存储名，否则 404 | `backend/app/routers/files.py:160` |
| 4 | 第二道关卡：`Path.resolve()` 后确认路径仍位于 `uploads/` 之内，否则 404 | `backend/app/routers/files.py:160` |
| 5 | 用 `FileResponse` 返回，`filename=` 传原始名（中文自动编码进 `Content-Disposition`） | `backend/app/routers/files.py:160` |
| 6 | 大文件下载由 `FileResponse` 自己处理 Range 断点续传与 `Content-Length` | Starlette 内置 |

两道关卡共同挡住 `/api/download/../../app.db` 这类请求；`tests/test_files.py`
里有对应的回归用例。

### 2.6 WebSocket 与 HTTP 的关系（`/ws`）

WebSocket **不是另一套网络栈**，它跑在 HTTP 之上，用同一个端口：

| 步骤 | 说明 | 位置 |
|---|---|---|
| 1 | 页面用 `ws://` / `wss://` 连 `/ws?user=&room=` | `frontend/js/common.js:68`（`wsUrl`） |
| 2 | 浏览器发出带 `Upgrade: websocket` 的 **HTTP GET**（查询串就是握手参数） | 协议层，无需本项目代码 |
| 3 | 服务端 `await ws.accept()` 回 `101 Switching Protocols`，HTTP 阶段结束 | `backend/app/routers/ws.py:96` |
| 4 | 回发 `welcome`（含在线名单、聊天历史、画布历史） | `backend/app/routers/ws.py:84` 附近 |
| 5 | 向房间广播 `join` | `backend/app/routers/ws.py:112` |
| 6 | 之后循环处理 JSON 帧：`chat` / `draw` / `clear` / `ping` | `backend/app/routers/ws.py:84` 的消息循环 |
| 7 | 断开时注销连接并广播 `leave` | `backend/app/routers/ws.py:226` |

由此得出的两个结论：

- **不需要为 WebSocket 额外开放端口或防火墙规则**，它和页面共用 `8000`。
- 页面用 `https` 打开时，必须用 `wss`，否则浏览器按混合内容拦截（`common.js:68` 已自动按 `location.protocol` 切换）。

### 2.7 静态前端是如何被 HTTP 提供的

`backend/app/main.py:138` 挂载了 `StaticFiles(directory=frontend, html=True)`：

| 请求 | 实际读取的文件 |
|---|---|
| `GET /` | 先被 `main.py:125` 的 `index()` 重定向到 `/index.html` |
| `GET /index.html` | `frontend/index.html` |
| `GET /blog.html` 等 | `frontend/*.html` |
| `GET /js/common.js` | `frontend/js/common.js` |

`html=True` 让目录请求自动回落到 `index.html`；静态目录位置可用 `APP_FRONTEND_DIR` 覆盖（`backend/app/config.py`）。

### 2.9 状态码约定

| 状态码 | 什么时候出现 | 位置 |
|---|---|---|
| `200` | 列表、详情、上传成功、下载、删除成功 | 各路由默认值 |
| `201` | 创建文章成功 | `backend/app/routers/blog.py:84` |
| `302` | 未登记昵称访问页面 → 跳转登记页 | `backend/app/auth.py`（`IdentityMiddleware`） |
| `307` | `GET /` 重定向到 `/index.html` | `backend/app/main.py:204` |
| `401` | 未登记昵称访问接口 | `backend/app/auth.py`、`backend/app/main.py:102` |
| `404` | 文章/文件不存在，或下载路径穿越 | `blog.py:65`、`files.py:160`、`files.py:185` |
| `413` | 上传超过 `MAX_UPLOAD_BYTES` | `backend/app/routers/files.py:81` |
| `422` | 请求体校验失败（框架自动返回，不进入函数体） | `backend/app/schemas.py` 的约束 |
| `500` | 写盘等意外错误 | `backend/app/routers/files.py:81` |

错误响应统一是 `{"detail": "人话说明"}`，前端 `common.js:19` 会把它转成 `Error.message` 直接显示。

### 2.10 前端 HTTP 客户端

所有请求都经过 `frontend/js/common.js:19` 的 `request()`：

- 自动按 `Content-Type` 决定 `res.json()` 还是 `res.text()`；
- 非 2xx 统一抛 `Error(detail)`，页面只需 `try/catch` + `toast(err.message)`；
- 收到 `401` 时自动跳转登记页（身份过期的情况）；
- `frontend/js/common.js:31` 的 `api` 对象提供 `get` / `post` / `del` / `upload` 四个方法，
  其中 `upload` 用 XHR 而非 `fetch`，只为拿到上传进度事件。

### 2.11 身份是怎么插进来的

| 环节 | 位置 | 关键点 |
|---|---|---|
| 昵称规范化 | `backend/app/auth.py`（`normalize_name`） | 折叠空白、限长 24 字，空名直接拒绝 |
| 放行清单 | `backend/app/auth.py`（`PUBLIC_PATHS`） | 只有健康检查、登记页、登记/退出/会话接口、CSS 与通用 JS 免登记 |
| 签发 | `backend/app/auth.py`（`make_token`） | Cookie 值 = `base64(昵称).到期时间戳.HMAC 签名`，服务端不存状态 |
| 校验 | `backend/app/auth.py`（`verify_token`） | 验签 + 查过期，通过则返回昵称 |
| 拦截 | `backend/app/auth.py`（`IdentityMiddleware`） | 纯 ASGI 实现，所以**能看到 WebSocket**；`BaseHTTPMiddleware` 做不到 |
| 登记 | `backend/app/main.py:102` | 记录昵称并下发 HttpOnly Cookie（30 天） |
| 换名字 | `backend/app/main.py:131` | 删除 Cookie，回到登记页 |
| 业务取用 | `backend/app/auth.py`（`current_user`） | 路由用 `Depends(current_user)` 拿到昵称，写入作者/上传者/发起人 |
| 前端登记页 | `frontend/login.html` + `frontend/js/login.js` | 成功后跳回 `?next=`，并校验 next 只能是站内相对路径 |
| 顶栏状态 | `frontend/js/common.js`（`initAuthUi`） | 显示当前昵称 + 「换个名字」 |

**为什么身份必须覆盖 WebSocket**：昵称不再由前端传参，而是从 Cookie 解析后写入
`ws.state.user`。如果只保护 HTTP，别人直接连 `/ws` 就能用一个随手编的名字发言；
现在聊天、画布里的名字与发文、传文件的作者必然是同一个。

```powershell
.\.venv\Scripts\python.exe scripts\gen_api_doc.py
```

本文（`docs/代码导读.md`）讲的是结构与顺序，不随行号频繁变动；需要精确行号时一律查自动生成的接口清单。
